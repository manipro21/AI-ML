# Multi-Agent Swarm Benchmark

A benchmark for evaluating whether multi-agent AI systems outperform single agents on tasks that are structurally too large for one agent to solve reliably. Built on the [Harbor](https://github.com/harbor-framework/harbor) evaluation harness with Docker-based execution, LLM-as-judge evaluation, and Kimi K2.5 via Fireworks API.

---

## What Changed: Harbor Migration

This project has migrated from a custom harness to **Harbor-style task format**. The previous harness (runner.py, cli.py) is archived in `resources/deprecated/`.

**Key changes:**
- Tasks are now in Harbor format: `instruction.md`, `task.toml`, `decomposition.yaml`, `environment/Dockerfile`, `tests/`, `solution/`
- Two custom agent classes added to Harbor: `swarm-kimi-single` (tool-restricted) and `swarm-kimi-multi` (full tools + decomposition injection)
- LLM judge scores 0.0–1.0 with field-by-field justification
- Execution logs saved inside each task directory
- Harbor diff file at `resources/swarmbench_harbor_changes.diff`

## Quick Start

### Prerequisites

- Docker Desktop running
- [uv](https://docs.astral.sh/uv/) installed (`curl -LsSf https://astral.sh/uv/install.sh | sh`)
- Fireworks API key

### Setup (one-time)

**Step 1: Clone this repo**
```bash
git clone https://github.com/turing-genai-apps/Multi-Agent-Swarm-Benchmark-.git
cd multi-agent-swarm-bench
```

**Step 2: Clone Harbor framework at pinned commit**
```bash
git clone https://github.com/harbor-framework/harbor.git
cd harbor
git checkout 4f6bea2a57cc60dee37868b68138a1ddc6898874
cd ..
```

> The commit SHA is pinned to ensure all team members get identical Harbor state and the diff applies cleanly. Do not skip this step.

**Step 3: Apply SwarmBench agent patches to Harbor**
```bash
cd harbor
git apply ../resources/swarmbench_harbor_changes.diff
```

This adds two custom agent classes (`swarm-kimi-single`, `swarm-kimi-multi`) and registers them in Harbor's agent factory. The diff modifies 3 files and adds the `swarmbench/` package:
- `src/harbor/models/agent/name.py` — enum registration
- `src/harbor/agents/factory.py` — agent class registration
- `src/harbor/trial/trial.py` — task_dir passthrough for multi-agent
- `src/harbor/agents/installed/swarmbench/` — agent classes + prompts (new)

**Step 4: Install Harbor dependencies**
```bash
uv sync --all-extras
```

**Step 5: Verify installation**
```bash
uv run harbor --version
# Expected: 0.3.0 (or latest)
```

**Step 6: Set API key**
```bash
export FIREWORKS_API_KEY=your_key
```

> To update Harbor in the future: regenerate the diff against the new commit, update the SHA in this README, and re-apply. Do not `git pull` without updating the diff — it may conflict.

### Run a Task

```bash
# Set your task
TASK=../example_tasks/4c3c848bb2f9459cb908d78f02897c6f-SWARMBENCH-FANOUT-RESEARCH-MEDICALRESEARCH

# Oracle validation (expected: reward = 1.0)
uv run harbor run -p $TASK -a oracle \
  --ve FIREWORKS_API_KEY=$FIREWORKS_API_KEY

# Single agent (1 run)
uv run harbor run -p $TASK -a swarm-kimi-single \
  -m fireworks_ai/accounts/fireworks/models/kimi-k2p5 \
  -k 1 -n 1 \
  --job-name "single-kimi-agent" \
  --jobs-dir "$TASK/execution_logs" \
  --ve FIREWORKS_API_KEY=$FIREWORKS_API_KEY \
  --ae FIREWORKS_API_KEY=$FIREWORKS_API_KEY \
  --quiet

# Multi agent (1 run)
uv run harbor run -p $TASK -a swarm-kimi-multi \
  -m fireworks_ai/accounts/fireworks/models/kimi-k2p5 \
  -k 1 -n 1 \
  --job-name "multi-kimi-agent" \
  --jobs-dir "$TASK/execution_logs" \
  --ve FIREWORKS_API_KEY=$FIREWORKS_API_KEY \
  --ae FIREWORKS_API_KEY=$FIREWORKS_API_KEY \
  --quiet
```

### Run All Tasks

```bash
bash resources/scripts/run_all_tasks.sh
```

## Task Format (Harbor)

```toml
# task.toml
[task]
name = "swarmbench/{task_id}"
description = "..."

[metadata]
verifier_type = "llm-judge"              # or "executable"
domain = "knowledge-research"            # code-swe / data-analysis / planning-operations / reasoning-math
coordination_pattern = "fan-out-synthesize"  # or "map-reduce"
human_solving_hours_estimate = 120.0
human_solving_hours_justification = "..."
estimated_sub_agents = 19
input_token_estimate = 500000
reference_link = "https://..."
why_multi_agent = "..."

[agent]
timeout_sec = 3600

[verifier]
timeout_sec = 600

[environment]
cpus = 2
memory_mb = 4096
build_timeout_sec = 600
```

## Performance Results

| Task | Domain | Pattern | Single Agent | Multi Agent | Gap |
|---|---|---|---|---|---|
| AGENTBENCHLANDSCAPE | knowledge-research | fan-out | 0.393 | 0.926 | **53 pts** |
| VENDORCROSSREF | data-analysis | specialist | 0.654 | 0.872 | 22 pts |
| MEDICALRESEARCH | knowledge-research | fan-out | 0.493 | 0.950 | **46 pts** |

Oracle achieves 1.0 on all tasks. Multi-agent consistently outperforms single-agent.

## Coordination Patterns (Phase 1)

| Pattern | Structure | When to use |
|---|---|---|
| **Map-Reduce** | N parallel shards → aggregator | Large datasets, structurally similar chunks |
| **Fan-Out / Synthesize** | N parallel threads → synthesizer | Multi-source research, independent analysis threads |
